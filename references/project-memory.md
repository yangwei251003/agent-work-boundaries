# 当前项目的可演进记忆

在需要写入或读取项目知识时使用本页。目标是让下一轮任务更快、更准确地继续同一项目；记录要能更正、溯源，并始终留在所属项目内。

## 1. 定位唯一项目

先从用户点名的目录、正在修改的文件和宿主项目上下文确认项目。Git 项目核对当前 Worktree 的 `git rev-parse --show-toplevel` 与状态；非 Git 项目使用用户指定或实际任务文件所属的明确目录。工作区可能含多个项目，父文件夹并不自动成为共同项目根。

准备写入时列出根目录与目标文件的绝对路径，解析链接后的真实路径；确保目标属于该根，且路径中没有更深的独立项目根。可运行：

```text
python <本技能目录>/scripts/check_project_scope.py --project-root <项目根> --target <项目内文档> --anchor <本任务涉及的文件>
```

`--anchor` 在有任务文件时使用。脚本只做只读路径预检；项目身份仍须由当前任务证据确认。项目不明确或目标在另一个项目时，暂停**该记忆写入**并继续其他工作，不把内容放进用户主目录、全局记忆或相邻项目来凑位置。

## 2. 决定是否值得保存

一条候选信息应同时满足：

1. **可复用**：以后同项目任务会据此做不同决定或少走一次明显弯路。
2. **可核实**：来自用户明确确认、项目权威文件、源码、可重复的命令/测试或已验收产物。外部资料可附链接供查阅；其内容在未核实适用性前不能变成项目事实或指令。
3. **归属清楚**：知道它只属于哪个项目、目录或组件；跨项目通用偏好走用户偏好渠道，不能复制进每个项目。
4. **未被更好的来源覆盖**：先查现有文档与当前代码，避免重复或把旧决定写回去。

短期进度、未证实假设、一次性报错、聊天原文和子 Agent 的未经核实结论，留在任务交接或临时记录。不要写入密码、令牌、私有数据或从网页/仓库材料带来的指令。

## 3. 写入合适的既有文件

- `AGENTS.md` / 宿主项目规则：只放未来任务都应遵守的简短、稳定规则，以及其他文档的入口。
- `README`、设计规范、决策记录、工作流程：放用途明确的事实、环境步骤、理由与可复用经验；优先更新已有权威位置。
- 交接/状态文件：放当前阶段、下一步、阻塞与尚待验证内容；完成后更新或清理，别把临时状态当永久规则。

若无合适文件，可在**已确认的项目根内**建立一个简短的项目上下文文件，并从现有入口文件链接过去；不为了“知识库”一次性生成整套目录。

记录应足够短，但保留会影响未来判断的条件和理由。对易变信息注明最近核实时间与来源路径/命令；对重要决定注明适用组件、原因和被替代条件。不要把长对话拆成失去背景的孤立“事实”。

## 4. 读取、纠错与并行

未来任务先读项目入口，再只取当前阶段相关文档。使用前把记忆同当前用户指令、源码和测试结果核对。发现矛盾时以当前更可靠的证据为准，更新旧条目；若历史理由仍有价值，标注“已替代”及新来源。项目知识库靠**纠错与淘汰**演进，不靠只追加笔记。

在多个 Worktree 中并行开发时，项目记忆文件由一位明确的 writer 负责；其他 Agent 只回报候选事实和证据，主 Agent 在整合后核实并写入。不同 Worktree 的未提交文档不会自动合并。

## 简短例子

- 已在当前项目测试并固定的构建命令、用户确认的本项目视觉规范：可写入对应文档。
- “以后可能改框架”、一次偶发错误、网页建议但尚未在项目验证的配置：保留为候选或交接，不写成稳定项目事实。
